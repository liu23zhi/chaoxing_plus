# 原生客户端与浏览器联动

## 目标与已确认范围

新增 Win32 一级主页，保留考试客户端选择、注入与运行流程作为二级入口。主页能够启动多个 Edge / Chrome 临时会话，每个会话使用独立配置目录和真实扩展，关闭会话后删除其资料。支持公共设置注入及每个新会话的覆盖设置。

扩展只从 tikuAdapter 在线获取，原生 EXE 不内嵌 CRX，也不提供本地文件入口。每次新会话查询并下载当前版本，失败时明确提示，已启动会话保持其版本。Edge 首发 ID 为 `lcmeenlnjihhjcjoakekikoaldigonac`。用户提供的本地文件仅用于早期兼容性验证，不作为产品依赖。Node 宿主保持冻结。

tikuAdapter 新增 Edge 扩展检查与缓存下载，保留 Chrome 来源接口。原生客户端复用既有验证码、账号登录和访问令牌协议，也允许直接输入 API key。

扩展更新开关、周期与两种商店的扩展 ID 通过 tikuAdapter 管理后台设置并持久化，保存后动态生效；环境变量只提供首次部署的可选默认值。

## 实现决策

- 使用普通安装的浏览器和独立临时 user-data-dir，不使用会禁用扩展的 Guest/Incognito 作为扩展运行环境。
- 采用 Chromium 官方 CDP pipe 和 `Extensions.loadUnpacked` 加载真实解包扩展；不依赖现代 Chrome 已移除的 `--load-extension`。
- 仅管理自身启动的浏览器进程树和会话目录；浏览器正常退出、主页关闭与启动失败都回收会话。处理失败时必须保留错误信息，不谎报清理成功。
- 设置采用既有共享键规则。公共设置与覆盖设置分开保存于当前程序内存，会话启动时合并；会话内也可使用扩展本身的设置界面。
- 凭据默认仅存当前进程内存；密码登录遵守现有验证码，JWT用于账号接口，API访问令牌用于题库请求。不得将密码/JWT写入日志或 URL。
- 主页对耗时启动/网络操作使用工作线程；原考试流程仍由既有宿主实现，不修改其注入协议。
- 服务端公开 latest/download 仅提供扩展分发，不扣费；刷新使用管理员鉴权，后台更新跟随进程 context 停止。下载失败保留已校验缓存。

## 验收与证据

必须验证真实 Chrome/Edge 的扩展加载、两个会话存储隔离、设置注入和退出清理；Win32主页/账号/设置窗口验证图标、布局、导航与按钮。服务端使用可控 HTTP 服务验证更新、无更新、损坏包、并发与失败保留旧包，另记录官方 Edge 的只读检查结果。

代码完成后执行扩展类型检查、构建、Windows构建、原生编译和完整 scripts 测试，服务端执行相应 Go 测试及全量测试。模拟页面与真实浏览器证据不能替代真实超星课程/考试客户端验收。未经逐项验证不得标记整个目标完成。
